# ST Git Improve

SillyTavern / Luker 的**纯前端扩展**：在酒馆内完成私有 git 源多账号登录、认证安装、
扩展更新、治理清理与诊断。主路径全部在「浏览器 + 宿主原生通道」内闭环，零服务端依赖；
可选接入 **Authority** 基石插件（经其公开适配层，仅对管理员）解锁服务端管理能力。
**纯补充面板**——不修改、不接管原生扩展管理的任何行为。

面板自动探测运行形态，以**三态徽标**标识：**纯前端** / **+Authority 增强**（非管理员）/
**+Authority 管理员**；管理功能按钮**常显**，无对应能力时灰化并提示解锁条件。

|---|---|---|

| 安装页通道提示 / 远端分支列举 | ✅ 分支经站点 API 列举（CORS 友好，凭据已有） | ✅ 另有服务端列举（增强） |

## 解决什么问题

| 原生痛点 | 本扩展方案 |
|---|---|
| 私有 git 站点（Gitea/GitHub/GitLab/Gitee…）无法下载扩展 | 站点凭据：PAT / 账号密码自动换 token / userinfo URL 提取，多账号逐个登录 |
| 扩展更新遇本地改动报 409 冲突，只能重装 | 纯前端：删旧+重装（明确提示改动不备份）；+Authority：重建式更新（depth-1 fetch → 候选树校验 → 本地改动自动 commit 到备份 ref → 原子重建，可恢复） |
| 服务端扩展更新后依赖缺失，要手动 npm install | +Authority：依赖修复（本体/任意扩展目录，可选 lock 重建） |
| 数据包导入/手动装产生的本地扩展与管理员全局版重复，浪费空间 | 去重扫描清理（纯前端：显式确认 + 风险提示删副本；+Authority：无改动守卫 + 启动自动清理） |
| 不用的自装扩展仍被宿主加载，占运行资源；删了怕丢数据 | **扩展治理**：停用/启用（宿主开关，目录与数据不动）；+Authority 另有整目录停用区（数据随目录保存）与确认后彻底清理 |
| 依赖系统 git 的环境配置（credential helper/insteadOf） | 浏览器内克隆走 isomorphic-git（纯 JS），零系统 git 依赖 |

## 安装

以**用户扩展目录**形式安装（纯前端，无需服务端插件、无需改 `config.yaml`）：

- 方式一：酒馆「扩展管理器」填入本仓库 Git URL 一键克隆；
- 方式二：手动拷贝本仓库到 `data/<user>/extensions/st-git-improve/`。

刷新页面后，**扩展设置抽屉**（左侧扩展菜单 Extensions → 本扩展）出现 **「Git 源管理」** 面板。

> 原服务端插件承载的管理能力（重建式更新与备份、npm 依赖修复、去重清理、整目录停用区、
> SSH/file 桥与代理）已移交 **Authority** 基石插件，仅对管理员开放；未安装 Authority 时
> 这些功能在面板中灰化并标注解锁条件，其余功能全部可用。

## 使用

面板**唯一注入点 = 扩展设置抽屉**（宿主原生扩展菜单 → 本扩展）；聊天区/输入区/顶栏/
消息旁零注入、零额外按钮。

**总览首屏（三件套）**

1. **运行环境卡**：三态徽标、宿主版本、面板版本对、浏览器克隆能力、凭据存储、
   Authority 能力态、（多用户时）当前用户。
2. **分区状态摘要**：每区一行（已装 / 可更新 / 停用 / 重复计数），点击跳对应分区。
3. **快捷动作区**：全部更新 · 全量扫描 · 面板自更新检查（结果内联反馈，完成后回写分区摘要）。

**三个分区**

1. **我的扩展**（安装/更新/诊断修复）：顶部安装入口——粘贴仓库地址（可带分支）即时显示
   将走的克隆通道与凭据来源，远端分支经站点 API 列举供下拉选择，SSH/file 地址即时红字警示
   不可用；常驻已装列表（宿主 discover 全量，无需先扫描）；行内操作——更新（仅登记来源者；
   删旧+重装并明确提示本地改动不备份）、卸载（官方 Popup 强确认，不可恢复）、迁全局/迁本地。
   全量扫描展示已装 / 可更新 / 远端状态三维；依赖缺失、manifest 损坏、本地改动列在
   无对应能力时灰化标注「需 Authority」。克隆成功后可一键导出本地 zip 副本；
   装完即被原生扩展系统识别。
2. **治理与清理**（停用启用/去重/台账）：停用/启用（宿主 `disabledExtensions` 开关，
   目录与数据完全不动，刷新生效）、一键全部停用/全部启用、去重扫描与清理（删除副本
   无「无改动守卫」，需显式确认 + 风险提示）、治理台账（本地记录于宿主设置）；
   整目录停用区、彻底清理释放磁盘、启动自动清理仅 +Authority 管理员态可用。
   本扩展自身的管理面板不允许被停用（否则治理入口自灭）。
3. **账号与设置**（凭据/偏好）：每个站点**逐个登录**多个账号——选类型 →（自建填地址）→
   填 PAT（或粘贴 `https://user:token@host/...` 自动提取）→ 添加，保存后自动验证；
   ☆/★ 切换站点默认账号；全部测试；JSON 导出/导入；凭据全程脱敏展示。
   设置项就地分散在本区（去重颗粒度、自动清理等；+Authority 态生效项灰化标注）。

面板更新检查（总览快捷动作）：对比 origin 仓库最新 manifest 版本，显示「已是最新 /
有新版本 + 打开发布页」（公开仓经 api.github.com，无需凭据）。

## 安全

- 凭据只存浏览器侧：事实源 = 宿主通用扩展数据位（`extension_settings`，经宿主设置保存接口
  随服务端 `settings.json` 持久化）；localStorage 仅在写入失败时兜底暂存，恢复后回写并清除，
  **永不作为任何数据的事实源**。
- 凭据不写入任何 URL、`.git/config` 或日志；前端展示一律脱敏。
- 调用 Authority 时，凭据按请求在内存中注入、即用即弃，**不在 Authority 侧落盘存储**。
- 仅支持 http(s) 克隆；不支持 SSH / LFS / submodule / hook 执行（SSH/file 经 Authority
  管理员能力另行提供）。
- 面板不新增任何本机服务端点；仅经宿主公开扩展通道与站点公开 API 通信。

## 开发

```bash
npm install

npm run standalone  # 启动 standalone 开发预览壳（端口 3040，仅开发用，见「已知边界」）
```

测试覆盖：URL 规范化/脱敏、路径安全校验、凭据存储与匹配、
i18n 键完整性（引用键必在字典、死键报警）、
能力态矩阵（宿主通道 × Authority × 管理员三维逐功能断言）、
确认流（强确认触发条件 + 后果文案完整性）。

## 已知边界（明确不做清单）

以下能力**明确不做**，均为浏览器物理限制或能力归属使然，非实现暂缺：

- **OAuth 设备码登录**（GitHub/GitLab device flow）：浏览器直连 OAuth 端点被 CORS 拦截，
  物理不可行；且设备码登录非管理功能，不进入 Authority 移交范围。
  PAT / 账号密码 / userinfo 三种登录方式不受影响。
- **纯前端 SSH / file / git:// 桥**：浏览器无法执行系统 git，物理不可行；此类地址在安装页
  红字提示不可用，请改用 https + token。系统 git 桥（`git@host:path`、`ssh://`、`file://`、
  `git://`，凭据走你自己的 ssh-agent）已移交 Authority（管理员）。
- **纯前端服务端代理**：isomorphic-git 不读系统代理环境变量，浏览器克隆走浏览器自身的
  代理设置；显式代理配置（直连 / 跟随环境变量 / 自定义地址）随 Authority git 桥提供。
- **纯前端 npm 依赖修复**：浏览器无法执行 npm，物理不可行，入口不显示；已移交 Authority（含本体）。
- **纯前端整目录停用区**：整目录搬移与彻底清理需要服务端文件操作；纯前端停用/启用走宿主
  `disabledExtensions` 开关（目录与数据不动），治理台账为本地记录。
- **纯前端备份恢复**：纯前端更新为「删旧+重装」，不产生备份，故无恢复入口；重建式更新与
  备份管理（git 备份 ref 的恢复/删除）已移交 Authority。

**standalone 开发预览壳**：`standalone/` 目录为**开发用途**的脱机预览壳（上游 public/ 静态
快照 + hook 伪造原生 API），经 `npm run standalone` 在 **3040** 端口启动；仅用于面板 UI 开发
（写操作提示「脱机预览不执行」并返回演示结果），**不随扩展分发**，与生产安装无关。

其他边界：

- 多用户：管理员判定经宿主会话的 admin 标志（多用户模式）；单用户/降级模式视为管理员。
- 纯前端网络约束：GitHub/GitLab 的 git 端点不发 CORS 头，浏览器内直接克隆会失败——安装主路径
  走宿主原生通道（服务端克隆），站点 API 预检（api.github.com 等支持 CORS）负责提前给出
  401/404 的清晰错误；克隆仅在可达时提供 zip 导出增强。
- 纯前端宿主通道约束（实测 ST 1.19）：宿主安装端点不支持覆盖（409）——更新语义为
  「删除旧目录+重装」，扩展目录内的本地改动不备份；停用清单写
  `extension_settings.disabledExtensions`（重载生效）。
- Gitee 账号密码换 token 依赖应用注册，推荐 PAT / userinfo。
- 本扩展自身的更新：面板自更新检查对比 origin 仓库最新 manifest 版本（公开仓经
  api.github.com，无需凭据），更新动作走宿主原生扩展更新通道，不依赖本扩展。
